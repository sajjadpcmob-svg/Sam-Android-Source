# سام — نسخه‌ی نیتیو اندروید (v3.3.1)

یک دستیار نیتیو **تک‌کاربره** و فارسی‌محور برای گوشی Samsung Galaxy S24 Ultra (۱۲ گیگابایت رم)، اندروید ۱۷. نام پکیج: `ir.elviran.sam`. شامل سوابق شخصی تک‌کاربره، کنترل و وضعیت تولید کارخانه، ورودی/خروجی صوتی، یک نقطه‌ی اتصال اختیاری هوش مصنوعی آنلاین و **یک LLM مولد واقعی روی دستگاه (llama.cpp، اختیاری)** است. حساب‌های چندکاربره و نقش‌ها پیاده‌سازی نشده‌اند.

> این فایل نسخه‌ی فارسی `README.md` است. برای جزئیات فنی یکسان به انگلیسی، همان فایل را ببینید.

## بیلد روی گیت‌هاب (GitHub Actions)

۱. این ZIP را باز کنید و **محتوای پوشه‌ی `SAM-Native`** را در ریشه‌ی ریپوی خود بارگذاری کنید (نه خود پوشه‌ی دربرگیرنده).
۲. روی شاخه‌ی `main` کامیت کنید.
۳. به **Actions → Build SAM Android APK → Run workflow** بروید (یا به `main` push کنید).
۴. آرتیفکت `SAM-debug-apk` را از اجرای موفق دانلود کنید.

### بیلد APK با هوش مصنوعی آفلاین (llama.cpp)

بیلد نیتیو llama.cpp **اختیاری** و به‌صورت پیش‌فرض خاموش است تا بیلد معمولی هرگز نشکند. برای ساخت APK با LLM آفلاین:

- وارد **Actions → Build SAM APK (Offline AI / llama.cpp) → Run workflow** شوید. این ورک‌فلو NDK و CMake را نصب می‌کند، `libsamllama.so` را برای `arm64-v8a` می‌سازد (با `-PsamLlama`) و آرتیفکت `SAM-debug-apk-offline-ai` را تولید می‌کند.
- وقتی این پرچم فعال نباشد، `LlamaNative.available == false` می‌ماند و اپ بدون کرش به مسیر آنلاین/فرمان درجا می‌کند.

ورک‌فلو از JDK 17 و Gradle 8.13 استفاده می‌کند، تست‌های واحد را اجرا و APK دیباگ را می‌سازد. **Gradle Wrapper واقعی** (`gradlew`، `gradlew.bat`، `gradle/wrapper/gradle-wrapper.jar` و `gradle-wrapper.properties` با `networkTimeout=60000`) داخل همین بسته کامیت شده است، بنابراین نیازی به نصب محلی Gradle نیست. این بسته شامل APK ساخته‌شده نیست.

## آنچه در این نسخه پیاده‌سازی شده است

- پوسته‌ی برنامه و ناوبری پایین با Kotlin + Jetpack Compose، تیره و راست‌به‌چپ (RTL).
- **موتور داده پویا:** کاربر ماژول‌های خود را می‌سازد، فیلدهایی از ۱۲ نوع (متن، متن بلند، عدد صحیح، اعشاری، تاریخ شمسی، زمان، تک‌انتخابی، چندانتخابی، بله/خیر، فایل، محاسباتی، رابطه) تعریف می‌کند، required/min/max/گزینه‌ها/پیش‌فرض را تنظیم می‌کند، ترتیب فیلدها را عوض می‌کند و رکوردها را در زمان اجرا اضافه/ویرایش/جست‌وجو/حذف می‌کند — **بدون تغییر کد و بدون جدول جدید**. ذخیره در Room (`dyn_modules` / `dyn_fields` / `dyn_records`)، داخل بکاپ و با یک موتور منطق خالص اعتبارسنجی می‌شود. فیلدهای محاسباتی فرمول‌هایی مثل `{قیمت}*{تعداد}` را با پارسر محدود محاسبه می‌کنند. **بدین ترتیب، بخش کارخانه داده‌محور است و قاعده‌ی هاردکد به کاربر تحمیل نمی‌شود.**
- **موتور تقویم شمسی** — کاتلین خالص، بدون وابستگی به ICU، با قاعده‌ی رسمی «breaks» برای سال کبیسه. سال **۱۴۰۳ را کبیسه** (۳۰ اسفند ۱۴۰۳ == ۲۰ مارس ۲۰۲۵) و **۱۴۰۴ / ۱۴۰۵ را غیرکبیسه** تشخیص می‌دهد، ۳۰ اسفند در سال غیرکبیسه را رد می‌کند و سررسید روز ۳۰ را در اسفند غیرکبیسه به ۲۹ می‌رساند. با تست واحد پوشش داده شده است.
- پایداری Room برای تاریخچه‌ی گفتگو، یادداشت‌ها، کارها، ورودی‌های مالی، کارخانه‌ها، خطوط تولید، ماشین‌ها، سفارش‌های تولید، حافظه‌ها، اسناد، رویدادهای ممیزی و تاریخچه‌ی چت. مهاجرت دیتابیس v4 → v5 جدول‌های قدیمی منابع انسانی را حذف می‌کند و سوابق شخصی و تولیدی را حفظ می‌کند.
- یادداشت‌ها، کارها، ورودی‌های مالی و حافظه‌ها از رابط کاربری ایجاد/ویرایش/حذف می‌شوند (تیک تکمیل کار هم هست). رکوردهای کارخانه/خط/ماشین/سفارش با بررسی وابستگی ایجاد/ویرایش/حذف می‌شوند تا رکورد یتیم نماند. ابرداده‌ی اسناد افزوده و حذف می‌شود.
- تاریخچه‌ی پایدار گفتگو در Room، داخل بکاپ محلی JSON و به‌صورت ۲۰ نوبت آخر به نقطه‌ی اتصال هوش مصنوعی داده می‌شود؛ به‌علاوه‌ی تشخیص گفتار فارسی (`fa-IR`) و Text-to-Speech اندروید در صورت نصب صدای فارسی.
- پیکربندی نقطه‌ی اتصال چت آنلاین سازگار با OpenAI؛ کلید API با Android Keystore رمزنگاری می‌شود.
- فراخوانی شبکه روی `Dispatchers.IO`؛ اعتبارسنجی اندپوینت به‌جز اندپوینت‌های توسعه‌ی محلی، HTTPS را الزامی می‌کند.
- پارسر محاسباتی محدود برای ارقام فارسی و انگلیسی؛ بدون اجرای کد پویا.
- سیاست ریسک اقدام که برای کارهای حساس/مخرب/خارجی تأیید می‌خواهد.
- بکاپ و بازیابی JSON نسخه‌دار (اکنون **v3**، شامل موتور داده پویا و تاریخچه‌ی گفتگو). بازیابی پیش از جایگزینی، داده و روابط رکوردها را در یک تراکنش Room اعتبارسنجی می‌کند؛ فایل خراب یا درج ناموفق کل بازیابی را برمی‌گرداند.
- **ابزار کارخانه:**
  - **قواعد ظرفیت تافی:** جمعه تعطیل؛ شنبه شروع ۰۷:۳۰؛ یکشنبه تا پنج‌شنبه ۰۷:۰۰؛ شنبه تا چهارشنبه ۷۵ بَچ (۷۲ خالص + ۳ ضایعات)؛ پنج‌شنبه ۵۴ (۵۲ خالص + ۲ ضایعات)؛ شست‌وشوی پنج‌شنبه ۲۴:۳۰ تا جمعه ۰۷:۰۰؛ جرم بَچ محصول پرشده ۱۵۶٫۵ کیلوگرم. نمای ۱۴روزه‌ی شمسی این ظرفیت‌ها را نشان می‌دهد.
  - **تقسیم بسته‌بندی کلاسیک کاوندیش:** مقادیر تلخ و میوه‌ای جدا نگه داشته و هرکدام به‌موازات بین بسته‌بندی دوسر و کوسن تقسیم می‌شود؛ پیش‌فرض ۷۰٪/۳۰٪ با نسبت قابل‌تنظیم.
  - **کنترل تولید:** باقیمانده‌ی سفارش را بر پایه‌ی ظرفیت روزانه به خطوط تخصیص می‌دهد، روز شروع/پایان و به‌موقع/تأخیر را نسبت به سررسید حساب می‌کند؛ سفارش‌هایی که خط ندارند یا ظرفیت صفر دارند «تخصیص‌نیافته» گزارش می‌شوند.
  - **وضعیت تولید / OEE:** دسترس‌پذیری × کارایی × کیفیت از دقایق برنامه/خرابی، نرخ ایده‌آل و شمارش کل/سالم، با برچسب درجه‌ی کیفیت.
- **مغز آفلاین پایه:** دستورهای محلی شناخته‌شده را بدون اینترنت اجرا می‌کند: ذخیره‌ی کار/یادداشت/درآمد-هزینه، محاسبه، و پاسخ به پرسش‌های پایه از روی رکوردهای محلی. این یک موتور قاعده/محاسبه‌ی قطعی است، **نه** یک LLM مولد روی دستگاه.
- فایل‌های تست واحد، پارسر محاسباتی، سیاست اقدام، موتور تقویم شمسی، منطق اعتبارسنجی/فرمول موتور داده پویا، زمان‌بند/OEE/قواعد کارخانه و مغز آفلاین را پوشش می‌دهند. GitHub Actions برای اجرای تست‌ها و ساخت APK دیباگ پیکربندی شده است.

## دستیار صوتی فارسی هندزفری (۳.۳.۱)

تب تازه‌ی `سام` یک دستیار صوتی پیوسته و بدون لمس روی چت push-to-talk موجود اضافه می‌کند (هر دو در دسترس می‌مانند).

- **عبارت بیدارباش «سام» روی دستگاه.** یک تشخیص‌گر محلی Vosk با گرامر کلیدواژه‌ی کوچک، «سام» را روی دستگاه می‌شنود؛ در مرحله‌ی شنود بیدارباش هیچ صدایی به سروری ارسال نمی‌شود. یک گِیت تطبیق به‌علاوه‌ی cool-down مانع شلیک مکرر یک گفته می‌شود.
- **مکالمه‌ی پیوسته‌ی هندزفری.** پس از «سام» دستیار می‌شنود، تشخیص می‌دهد، با TTS فارسی پاسخ می‌دهد و (در صورت فعال‌بودن) برای ادامه گوش می‌دهد — یک حلقه‌ی چندنوبتی کامل بدون لمس.
- **STT واقعی، آنلاین + آفلاین.** با اتصال شبکه و اجازه‌ی کاربر از `SpeechRecognizer` دستگاه برای `fa-IR` استفاده می‌شود؛ در غیر این صورت تشخیص واقعی آفلاین با Vosk (Kaldi) روی دستگاه اجرا می‌شود.
- **Barge-in.** هنگام صحبت سام، کاربر می‌تواند روی صدای او حرف بزند؛ تشخیص فعالیت صوتی TTS را فوری قطع و دوباره شروع به شنیدن می‌کند.
- **سرویس میکروفون پیش‌زمینه.** `VoiceForegroundService` حلقه را بیرون از Activity زنده نگه می‌دارد با نوتیفیکیشن پایدار و قابل‌کنترل کاربر (اکشن بی‌صدا/توقف) و نوع foreground-service از نوع `microphone` را که از اندروید ۱۴ لازم است اعلام می‌کند.
- **رابط صوتی.** گوی وضعیت متحرک، فاز زنده (منتظر «سام» / در حال شنیدن / پردازش / صحبت)، رونویسی لحظه‌ای، کارت‌های زیرنویس کاربر/دستیار، کارت نصب مدل آفلاین، و پنل تنظیمات صوتی شامل **کلید اصلی فعال/غیرفعال‌کردن دستیار صوتی**، حالت مصرف باتری، حساسیت بیدارباش، ترجیح آنلاین، ادامه‌ی خودکار و سرعت/زیروبمی گفتار.

### فعال/غیرفعال‌کردن دستیار صوتی
- در پنل تنظیمات تب `سام` یک سوییچ **«فعال‌بودن دستیار صوتی و عبارت «سام»»** افزوده شده است. وقتی خاموش باشد، زدن دکمه‌ی شروع حلقه‌ی شنود را آغاز نمی‌کند و اگر دستیار در حال اجرا باشد، خاموش‌کردن این سوییچ میکروفون را فوری متوقف می‌کند. این ترجیح در DataStore ذخیره و بین اجراها حفظ می‌شود.

### مدل فارسی آفلاین (Vosk)
- مدل آفلاین **همراه بسته نیست**؛ مدل کوچک فارسی Vosk (~۵۰ مگابایت، Apache-2.0) یک‌بار در زمان اجرا از تب `سام` («دانلود مدل آفلاین») دانلود و روی دستگاه کش می‌شود.
- تشخیص بیدارباش و STT آفلاین به این مدل نیاز دارند. اگر مدل نصب نباشد، دکمه‌ی «صحبت با سام (شروع دستی)» همچنان امکان آزمایش STT آنلاین را فراهم می‌کند؛ اما بیدارباش «سام» و STT آفلاین تا نصب مدل فعال نمی‌شوند.



### راه‌اندازی ضروری پاسخ‌گویی صوتی در اولین اجرا
۱. مجوز میکروفون را بده و در تب `سام` روی «فعال‌سازی سام» بزن.
۲. برای آزمایش بدون مدل Vosk، روی «صحبت با سام (شروع دستی)» بزن. سرویس تشخیص گفتار گوشی باید `fa-IR` را پشتیبانی کند؛ صرفاً آنلاین‌بودن اینترنت تضمین‌کننده‌ی وجود موتور فارسی نیست. برای کیفیت بهتر، سرویس گفتار فارسی و داده‌های زبان فارسی را در تنظیمات گوشی به‌روز/نصب کن.
۳. تشخیص گفتار (STT) و تولید پاسخ هوشمند (LLM) دو سرویس جدا هستند. برای پاسخ مولد آنلاین، از «تنظیم اتصال هوش مصنوعی آنلاین» وارد شو و endpoint سازگار با OpenAI، شناسه مدل و در صورت نیاز کلید API معتبر را وارد کن. این نسخه هیچ کلید یا اشتراک پولی از پیش ندارد؛ بدون تنظیم endpoint/model، پاسخ‌های عمومی هوشمند آنلاین کار نمی‌کنند و SAM فقط فرمان‌های محلی پشتیبانی‌شده را اجرا می‌کند یا پیام راهنما می‌دهد.
۴. برای پاسخ مولد آفلاین، APK را از Workflow `Build SAM APK (Offline AI / llama.cpp)` بساز، سپس در تب `سام` مدل GGUF را دریافت و بارگذاری کن. ساخت APK از Workflow عادی، کتابخانه‌ی `libsamllama.so` را شامل نمی‌شود.
۵. برای شنود بیدارباش «سام» و تشخیص گفتار آفلاین، مدل Vosk را از کارت «دانلود مدل آفلاین» نصب کن. این مدل با مدل GGUF هوش مصنوعی متفاوت است.

**رفع تداخل میکروفون:** در این نسخه، SpeechRecognizer آنلاین پیش از شروع ضبط VAD/TTS به‌صورت هم‌زمان آزاد می‌شود تا مالکیت میکروفون بین سرویس آنلاین و ضبط‌کننده‌ی داخلی تداخل نکند.

### مجوزها و حریم خصوصی
- مجوزهای زمان اجرا: `RECORD_AUDIO` (الزامی) و در اندروید ۱۳+ مجوز `POST_NOTIFICATIONS`. منیفست همچنین `FOREGROUND_SERVICE` / `FOREGROUND_SERVICE_MICROPHONE` و یک `<queries>` برای سرویس تشخیص/TTS اعلام می‌کند.
- صدای خام **هرگز** روی دیسک ذخیره نمی‌شود مگر کاربر صریحاً فعال کند (`allowRawAudio`، پیش‌فرض **خاموش**). هیچ کلید API هاردکد نشده؛ کلیدهای هوش آنلاین رمزنگاری‌شده در Android Keystore می‌مانند.
- ضبط در صورت پشتیبانی دستگاه از `AcousticEchoCanceler` / `NoiseSuppressor` / `AutomaticGainControl` استفاده می‌کند.

## هوش مصنوعی آفلاین روی دستگاه (llama.cpp — نسخه‌ی ۳.۳)

یک LLM مولد واقعی روی دستگاه با `llama.cpp` (نه Mock) افزوده شده و به همان مسیر پاسخ‌دهی موجود (`AiRouter`) وصل شده است.

- **سه حالت پاسخ‌گویی:** از تب `سام` ← تنظیمات ← کارت «هوش مصنوعی روی دستگاه» یکی از این حالت‌ها را انتخاب کنید: **فقط آنلاین**، **فقط آفلاین** (هیچ درخواست شبکه‌ای) یا **ترکیبی** (اگر مدل بارگذاری شده باشد آفلاین، وگرنه آنلاین).
- **دریافت مدل — داخل APK نیست.** از همان کارت، یک مدل GGUF (پیش‌فرض: `Qwen2.5-3B-Instruct` Q4_K_M) را انتخاب و دانلود کنید (حجم و در صورت pin شدن، SHA-256 بررسی می‌شود)، سپس «بارگذاری در حافظه» را بزنید. مدل در حافظه‌ی داخلی اپ ذخیره می‌شود و کاملاً آفلاین اجرا می‌شود.
- **ایمنی حافظه:** هر مدل حداقل RAM لازم دارد؛ اگر دستگاه کوچک‌تر باشد، دانلود/بارگذاری اجازه داده نمی‌شود.
- **دریافت دستی (adb):** می‌توانید فایل GGUF را جداگانه دانلود و از گزینه‌ی import استفاده کنید.
- **توجه نسبت به بیلد:** پاسخ آفلاین واقعی فقط وقتی کار می‌کند که APK با ورک‌فلوی «Offline AI» (پرچم `-PsamLlama`) ساخته شده باشد. در APK معمولی، کارت وضعیت را نشان می‌دهد ولی از مسیر آنلاین/فرمان پاسخ می‌دهد.

## آنچه پیاده‌سازی نشده است — به‌عنوان قابلیت موجود در نظر نگیرید

- حساب‌های چندکاربره و نقش‌ها/دسترسی‌ها. منابع انسانی، مدیریت کارکنان، حقوق و کسورات خارج از دامنه‌اند. ویژگی‌های کارخانه به برنامه‌ریزی تولید، وضعیت خط/ماشین، خروجی واقعی، خرابی، ضایعات، ظرفیت و OEE محدود است.
- **LLM مولد روی دستگاه** از طریق llama.cpp به‌صورت اختیاری پیاده‌سازی شده (بخش «هوش مصنوعی آفلاین روی دستگاه» را ببینید). مغز آفلاین پایه همچنان محاسبه‌گر/قاعده‌ی قطعی است و مستقل از LLM کار می‌کند.
- همگام‌سازی Google Drive/Calendar/Gmail یا Microsoft OAuth/Graph. بکاپ فقط خروجی/ورودی JSON محلی انتخابی کاربر است.
- بهینه‌سازی پیشرفته‌ی کارخانه (حل‌کننده‌ی چندقیدی/ظرفیت‌محدود)، تقویم شیفت، موجودی، کیفیت، نگهداری، تدارکات و گزارش‌های تفصیلی تولید. ابزار کنترل تولید و OEE ریاضیِ ظرفیت تک‌مرحله‌ای است، نه یک MES/APS کامل.
- دیتابیس Room رمزنگاری‌شده.
- تست‌های جامع UI/Instrumentation برای Compose.

هیچ کلید API یا راز OAuth در سورس تعبیه نشده است. هوش آنلاین اختیاری است و بسته به ارائه‌دهنده ممکن است هزینه داشته باشد.

## محدودیت‌های تأیید

اسموک‌تست‌های مستقل کاتلین برای تبدیل شمسی، OEE، زمان‌بندی عمومی تولید، قواعد ظرفیت تافی و تقسیم بسته‌بندی کاوندیش پاس شدند. فایل‌های XML درست پارس می‌شوند و در فایل‌های Compose تغییریافته خطای نحوی یافت نشد. یک بیلد کامل Android/Room/KSP + Compose با Gradle و مجموعه‌ی کامل JUnit در این محیط **اجرا نشده** است، چون Gradle یا Android SDK اینجا در دسترس نیست. بیلد کامل باید با یک اجرای سبز GitHub Actions تأیید شود، سپس APK روی دستگاه هدف نصب و تأیید گردد. بیلد سبز گیت‌هاب جایگزین تست روی دستگاه نیست؛ دقت بیدارباش، کیفیت STT/TTS و رفتار barge-in فقط روی گوشی واقعی تأیید می‌شوند.
